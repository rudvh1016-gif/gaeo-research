# Observation boundary and sequential DART evidence preservation

This isolated draft is based on Research #9 at `0687231947a251d249ab3d9679e6e585d77d44e0`. It is separate from budget follow-up #11, changes no stored data and must not be deployed or merged to main.

## Reproduced paths and scoped change

The builder read current list/evidence records even when its bundle timestamp came from an earlier complete coverage boundary. A later same-day observation could therefore be relabeled as earlier evidence. It now requires tracked list records' `detected_at` and each tracked evidence snapshot's response-completion `queriedAt` to be valid, timezone-aware and no later than the stated boundary. Unknown, later, conflicting or unreadable evidence stops the entire build; it is never silently removed to produce an empty/no-event result. The main entry point retains the previous published files on that rejection.

Per-record `observedAt` is emitted in the public filing fact. It is a claim from the stored input, not provider-authenticated proof. Equivalent consistent source copies use the earlier checked observation; differing titles or receipt dates cannot silently merge under one receipt ID. Fractional seconds in coverage boundaries are preserved so the builder cannot truncate the very observation it accepts. A boundary after the build time is rejected.

For DART raw segments only, a sequential retry cannot replace an existing record with different content or timestamps. Conflicts and duplicate stored/input keys reject the whole batch before a write. An exact retry returns the legacy matched-record count without rewriting even the original ciphertext. Ordinary research-prediction replacement behavior is unchanged. Existing DART record contents remain unchanged when new records are added, but the segment container is still rewritten; no physical append-only storage guarantee is claimed.

## Validation and limits

Windows/Python 3.14 targeted builder/freshness/archive suites: 31 tests passed. Existing archive-read ResourceWarnings were emitted. The initial full builder module run exposed two precision expectations and an old catch-up fixture that contained a post-boundary receipt; these were corrected to test precise timestamps and explicit rejection. Its remaining committed-output hash failure is the existing Windows checkout newline mismatch; no generated data was changed to hide it. Full exact-head Linux CI is required.

New regressions run against unchanged #9 reproduce one builder failure and four archive failure subcases, with zero errors. This demonstrates detection of the original paths; it is not a passing baseline result. New cases cover later same-day observations, missing/invalid/timezone-free timestamps, exact subsecond equality, timezone equivalence, empty evidence snapshots, conflicting sources, malformed/duplicate JSON, unchanged previous publication bytes, unchanged encrypted originals, mixed-batch conflicts and no collector acknowledgment of a changed retry.

A read-only build attempt against #9's frozen committed source snapshot stopped with `DISCLOSURE_RECEIPT_CONFLICT`; it did not write outputs. Existing source copies disagree and this draft does not choose or repair one. The first shell command for that probe had a quoting SyntaxError and did not execute; the corrected stdin script produced the reported rejection. This is a compatibility/reconciliation gate, not an observed production outage or a proven provider error.

This is NOT a complete point-in-time or immutable-history solution. Legacy `queriedAt` may have been recorded before its response and cannot be authenticated retrospectively. The seen registry, issuer evidence and financial stores still need versioned immutable snapshots and provenance; this patch does not restore any already lost original. Global-list receipt-date-prefix assumptions, complete raw coverage, the display cap, same-day provider truth, race-free archive/registry/merge writers, filesystem path replacement, locking, crash durability and independent backups remain unverified. A changed retry timestamp now safely blocks the batch but may prevent progress until retry reconciliation is designed; do not weaken the conflict guard to make it run.

Budget merge, post-replacement interruption accounting, save-failure quarantine, distributed reservations, midnight/send races and hard runner loss remain separate NO-GO conditions. Financial periods' observation semantics and downstream consumer compatibility also remain separate. No provider requests, service AI calls, production deployment, stored budget/ledger changes or paid resource provisioning are part of this work. Existing GitHub CI is the only remote execution requested; account billing is not verified.
